Investment Dashboard

A private portfolio operating system that turns scattered holdings, journals, watchlists, and admin tasks into a focused web app.

Open live demo ↗ View source ↗
AudiencePrivate investor / portfolio operator
RoleProduct thinking, frontend, backend, deployment
StackHTML, CSS, JavaScript, FastAPI, SQLAlchemy, PostgreSQL
StatusLive demo with production API and admin flows
01Problem

Portfolio decisions were spread across static files, manual notes, and repeat calculations.

The product needed one reliable place to read holdings, review trade journals, track watchlist ideas, and update operational data without editing JSON by hand.

02Solution

A static frontend backed by a clear API boundary.

  • Dashboard reads portfolio and journal data through FastAPI, with static fallback for resilience.
  • Admin UI supports authenticated CRUD for holdings, watchlist items, journals, and trades.
  • Production persistence uses PostgreSQL through SQLAlchemy and Alembic migrations.
  • Runtime config keeps frontend API URL and backend CORS explicit across local and production environments.

04Trade-offs

Keep the first product reliable before expanding the surface area.

The current admin model uses a bearer token entered in the browser for a private operator workflow. That is acceptable for this learning-stage private app, but a commercial multi-user product would need real login, account ownership, audit logs, and role-based access control.

05Commercial step

Turn the dashboard pattern into lightweight operating dashboards for small service businesses.

The reusable product shape is clear: leads, appointments, notes, revenue snapshots, reminders, and admin workflows for operators who need less complexity than a full CRM.

Case study / Wedding planning

Wedding Planner Demo

A niche-specific planner website for packages, planning timelines, vendor coordination, proposal inquiries, and lead follow-up.

Open live demo ↗ View kit case study ↗
AudienceBusy couples, families, and destination clients
RoleNiche positioning, package UX, lead workflow
StackHTML shell, shared CSS/JS, JSON content, FastAPI lead path
StatusReusable-kit demo with proposal inquiry capture
01Problem

Wedding clients need confidence that planning pressure will become a managed workflow.

A planner site has to clarify package fit, timeline responsibility, vendor coordination, and the next step before a couple is ready to book a proposal call.

02Solution

Reuse the service kit, then specialize it for wedding planning operations.

  • The demo reuses the Service Business Website Kit's shared CSS and JavaScript.
  • `data/site.json` changes the brand, package model, planning timeline, proof points, testimonials, moodboard, and FAQ.
  • The inquiry form is ready for the shared lead API introduced in P2-11.
  • The commercial path is planner website first, then proposal pipeline, vendor tracker, reminders, and event-week dashboard.
03Workflow
01

Capture date, venue status, guest count, budget range, and planning pressure points.

02

Move the lead into admin status: new, contacted, proposal sent, booked, or closed.

03

Expand later into vendor notes, reminders, proposal templates, and wedding-week operations.

04Trade-offs

The first version focuses on the lead path, not a full wedding planning platform.

Payments, calendar sync, vendor portals, and client login can wait. The smallest valuable workflow is inquiry capture, admin review, status update, and follow-up note.

05Commercial step

This becomes a reusable offer for planners and creative service businesses.

The same kit can support photography, wedding planning, salons, and other appointment-based businesses while the backend lead workflow stays shared.
